# ONLYOFFICE Document Server on Pterodactyl — custom egg

## Прочитайте это перед импортом

Pterodactyl/Wings по дизайну запускает контейнеры **без root** и без
переназначения портов (порт внутри контейнера обязан совпадать с портом,
который выделила панель), а часть системных путей внутри образа смонтирована
**read-only** (проверено: `/etc/onlyoffice/documentserver/nginx/...` даёт
`Read-only file system` при попытке записи). Официальный образ
`onlyoffice/documentserver` — это один контейнер, где supervisord поднимает
сразу nginx, docservice, converter и **свои внутренние
PostgreSQL/RabbitMQ/Redis**.

### Как этот egg обходит проблему с портом

Первая версия скрипта патчила nginx-конфиг ONLYOFFICE прямо на месте (`sed
-i`) — и упала с `Read-only file system`, потому что каталог с конфигом
недоступен для записи вообще, независимо от способа редактирования.

Текущая версия **не трогает конфиги ONLYOFFICE вообще**:

1. Запускает родной entrypoint (`/app/ds/run-document-server.sh`) в фоне —
   он поднимается на своём стандартном порту 80, как обычно.
2. Ждёт, пока `http://127.0.0.1/healthcheck` не начнёт отвечать.
3. Генерирует **отдельный, второй** конфиг nginx в `/home/container/`
   (это точно доступно для записи — это персистентный volume сервера) и
   запускает **второй, независимый процесс nginx**, который слушает именно
   тот порт, что выделил Pterodactyl (`${SERVER_PORT}`), и просто
   проксирует трафик на `127.0.0.1:80`, где уже работает настоящий
   Document Server.
4. Этот второй nginx и есть foreground-процесс, который видит панель
   (кнопка «Стоп», статус сервера).

Это решает именно проблему с портом/read-only. Проблему с root это **не
решает** — если supervisord/Postgres/RabbitMQ внутри не смогут переключаться
на нужных системных пользователей без root, Document Server может не
подняться до состояния «healthcheck отвечает», и скрипт сообщит об этом в
консоли (см. раздел «Если не запускается»).

Если и это не взлетит — рабочий и проверенный вариант остаётся в
`deploy/onlyoffice/docker-compose.yml` (обычный Docker на том же VPS, без
ограничений Wings).

## 1. Импорт egg в панель

1. Админка Pterodactyl → **Admin → Nests → Import Egg**.
2. Загрузите `pterodactyl-egg.json`.
3. Egg попадёт в отдельный Nest (или выберите существующий) с именем
   «ONLYOFFICE Document Server».

Если у вас уже был импортирован предыдущий вариант этого egg (тот, что падал
на `sed`) — переимпортируйте файл поверх (Admin → Eggs → открыть egg →
Import) и **переустановите** существующий сервер (Admin → Servers → сервер →
Manage → Reinstall Server), чтобы новый install-скрипт переписал
`start.sh`.

## 2. Создание сервера

1. **Admin → Servers → New Server.**
2. Выберите egg «ONLYOFFICE Document Server», Docker-образ
   `onlyoffice/documentserver:latest`.
3. **Ресурсы**: ONLYOFFICE официально рекомендует минимум 2 ядра / 2 ГБ RAM
   для Document Server в одиночку — с учётом встроенных Postgres/RabbitMQ
   внутри того же контейнера возьмите с запасом, 4 ГБ RAM разумнее.
4. **Allocation**: одна основная аллокация (порт) — её и получит
   проксирующий nginx.
5. Переменная **JWT Secret** — сгенерируйте `openssl rand -hex 32` и
   вставьте. Это же значение пропишите в `.env`/`config.py` NexusData как
   `ONLYOFFICE_JWT_SECRET` (см. основной `deploy/onlyoffice/README.md`,
   шаг 4 — там же и про mixed content/HTTPS, актуально и для этого пути).
6. Создайте сервер и запустите.

## 3. Если не запускается

Смотрите консоль сервера в панели — скрипт сам печатает, на каком шаге он
находится (`[egg] ...` строки):

- **`[egg] Document Server process exited early`** — сам
  `run-document-server.sh` упал до того, как healthcheck начал отвечать.
  Прокрутите лог ВЫШЕ этой строки — там будет настоящая причина. Самое
  вероятное: ошибки вида `could not change to directory`,
  `Operation not permitted`, `setuid failed` от supervisord/Postgres/
  RabbitMQ — это и есть проблема с отсутствием root у контейнера. Варианты:
  - Уточнить у администратора ноды, разрешает ли эта конкретная Wings-нода
    Docker-капабилити типа `SETUID`/`SETGID` для egg (нестандартная
    настройка, не входит в типовую установку Pterodactyl).
  - Поискать community-форк образа ONLYOFFICE, патченный под rootless-запуск.
  - Перейти на `docker-compose.yml` из этой же папки.
- **Зависает на `[egg] Waiting for Document Server...` дольше 5 минут**
  (60 попыток по 5 секунд) — процесс жив, но healthcheck не отвечает.
  Смотрите, не зависла ли внутренняя инициализация (тот же класс проблем,
  что выше, либо медленный старт на слабом железе — увеличьте цикл ожидания
  в install-скрипте, если ресурсов действительно достаточно, просто медленно).
- **Второй nginx не стартует** (`[egg] Forwarding ...` есть, но редактор не
  открывается) — проверьте `/home/container/proxy-error.log` внутри
  контейнера (доступен через файловый менеджер панели) и что порт из
  аллокации действительно совпадает с тем, что панель показывает для
  сервера.
- **Консоль не переключается в «Running»** — маркер для этого egg —
  `[egg] Forwarding` (последняя строка перед `exec nginx`), это я контролирую
  сам, а не гадаю по внутренним логам supervisord, так что должно сработать
  сразу.
